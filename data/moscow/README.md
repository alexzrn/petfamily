# Карта Москвы: формат данных и инструменты

## Файлы

- `spots.json` — рабочий набор точек (113 записей): клиники, площадки, приюты, передержка, груминг, магазины.
- `schema.json` — JSON-схема точки. Обязательные поля: `id`, `category`, `name`, `address`, `lat`, `lon`, `source`, `checked_at`. Необязательные: `district`, `phone`, `hours`, `site`, `price`, `open_24h`, `home_visit`, `inpatient`, `geo`.
- `validate.mjs` — проверка JSON-файла: `node data/moscow/validate.mjs data/moscow/spots.json`.
- `import-csv.mjs` — импорт CSV в JSON: `node data/moscow/import-csv.mjs <in.csv> <out.json>`.
- `examples/` — пример валидной точки.

## Правила

Категория — только `vet`, `boarding`, `grooming`, `park`, `shelter`, `shop`. Координаты в границах Москвы с запасом:
широта 55.10–56.10, долгота 36.70–38.50. `checked_at` — дата `YYYY-MM-DD`. `source` и `site` — URL `http(s)`.
Дубли ищутся по `id` и по паре «адрес + название» после нормализации.

Признаки `open_24h`, `home_visit`, `inpatient` ставятся в `true` только при явном указании в источнике, иначе `null`.
Телефон, часы работы и сайт переносятся из источника дословно; если в источнике их нет — `null`, а не выдуманное значение.

## Откуда взяты точки

| Категория | Источники |
| --- | --- |
| Клиники | `mos-obvet.ru/clinics/` (государственные клиники Мосветобъединения), `svoydoctor.ru/contacts/`, `vet.city/contacts/`, `zoovet.ru`, `vetclinika.moscow` |
| Приюты | `priut-ks.ru`, `priutnekrasovka.ru`, `solntsevo.mos.ru`, `pechatniki-pets.ru`, `rospriut.ru`, `dorinvest.ru`, `murkosha.ru` |
| Передержка | `ecoclub.pet`, `zootel.moscow`, `zoospace.net`, `bembivet.ru` |
| Груминг | `salon-milord.ru` (сеть «Милорд») |
| Магазины | `bethowen.ru/shops/<id>` (сеть «Бетховен») |
| Площадки и парки | OpenStreetMap через Nominatim, источник — ссылка на OSM-объект |

Поле `source` у каждой точки — конкретная страница, откуда взяты название, адрес, телефон и часы.

## Координаты

Координаты не выдумываются: адрес геокодируется через Nominatim (`https://nominatim.openstreetmap.org/search`) с
собственным User-Agent и паузой не меньше секунды между запросами. В поле `geo` записано, из какого OSM-объекта получена
точка (`nominatim:way/123`). Для парков координаты берутся прямо из OSM-объекта, `source` — его URL.

Геокодирование по адресу даёт погрешность до квартала, особенно для адресов вида «вл. 26» или «стр. 3», которых нет в
OSM отдельным зданием. На карточке точки координаты показаны, чтобы это было видно.
